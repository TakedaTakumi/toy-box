# グレゴリーメッシュエディタ試作

ケージ（点・辺・面のメッシュ）を編集すると、辺のベジェ曲線が自動で決まり、**四角形と三角形のグレゴリーパッチが G1 連続で貼られる**ブラウザ上の試作です。メタセコイア風の編集操作（選択モード、押し出し、ループ分割、ミラー、Undo）が、この曲面の上で成り立つかを確かめるための最小版です。

- 成果物：HTML と JavaScript（ES モジュール）。ビルドは不要
- 試作リンク：https://takedatakumi.github.io/toy-box/tools/gregory-mesh-editor/
- 数学の試作（頂点を動かすだけの版）を土台に、編集操作を足したもの

## 何を確かめるための試作か

| 問い | この試作での見せ方 |
| --- | --- |
| ケージ駆動型の操作でグレゴリー曲面を作れるか | 立方体や平面から、押し出しとループ分割で形を作る |
| 編集のたびに曲面が G1 連続のままか | 画面右の「連続性の検証」で、辺ごとの法線の最大差を表示する |
| ミラー編集が曲面でも自然に働くか | x=0 の面で左右対称に、選択・移動・押し出しを行う |

## 使い方

1. 「新しい形状から始める」で、立方体・平面・四角錐・三角柱から選ぶ
2. 選択モード（点・辺・面）を切り替え、要素をクリックして選ぶ。Shift（または Ctrl）を押しながらで追加・解除
3. 選んだ要素をドラッグして移動する。空所のドラッグは視点の回転
4. 面モードで面を選び、押し出しを行う。辺モードで辺を選び、ループ分割や折れ目の切り替えを行う
5. 形が崩れたら、元に戻す（Ctrl+Z）で戻す

### 操作とショートカット

| 操作 | ショートカット | 内容 |
| --- | --- | --- |
| 点・辺・面モード | `1` / `2` / `3` | 選択モードの切り替え。選択は、新しいモードの要素に変換される |
| すべて選択 / 解除 | `Ctrl+A` / `Esc` | |
| 押し出し | `E` | 選んだ面を、面の法線方向に押し出す（面モード） |
| ループ分割 | `L` | 選んだ辺と平行な辺を四角形の列にそって集め、すべて中点で分割する（辺モード） |
| 削除 | `Del` | 選んだ要素に接する面を削除する。使われなくなった頂点も取り除く |
| 折れ目の切り替え | `C` | 選んだ辺の G1 を切る。すべて折れ目なら解除する（辺モード） |
| ミラー編集 | `M` | x=0 の面で左右対称に編集する |
| シェーディング | `S` | スムース（法線をピクセルごとに補間）とフラット（細かい三角形ごとに面の向きで明るさを決める）を切り替える。初期値はスムース |
| 移動の軸 | `X` / `Y` / `Z` | 移動を軸に沿わせる。もう一度押すと自由に戻る |
| 元に戻す / やり直し | `Ctrl+Z` / `Ctrl+Shift+Z` | 100 回まで |
| 視点 | ドラッグ / ホイール / ＋－ | 空所のドラッグか右ボタンで回転。ホイールかピンチで拡大縮小 |

## 機能仕様

### 曲面の作り方

| 項目 | 内容 |
| --- | --- |
| 辺 | 3次ベジェ曲線。両端の接線は、頂点の法線に垂直な平面へ辺の向きを射影して決め、長さを辺長 × ハンドル長にする |
| 四角形の面 | 四角形グレゴリーパッチ（3次の境界曲線と、角ごとに2点の内部制御点） |
| 三角形の面 | 3次の境界曲線を4次のベジェ三角形に次数上げし、角ごとに2点の内部制御点を持たせたグレゴリーパッチ |
| G1 連続 | 辺ごとに両側の面で共有する接線場を決め、内部制御点をそこから求める |
| 頂点の法線 | 角度重みの面法線の和。折れ目で区切られた面のまとまりごとに持つ。接平面へ射影して角が裏返る場合は、重みなしの和、各面の法線の順に候補を替える |
| 折れ目 | 辺の曲線は両側の面で共有する（位置は連続）。辺の接線は両側の接平面の交線の向きにする |

### 編集操作の仕様

| 操作 | 仕様 |
| --- | --- |
| 押し出し | 選択した面を、頂点ごとの法線方向（選択面の法線の平均）へ、押し出し量だけ移動して複製し、境界に側面を足す。辺でつながった面の扇ごとに頂点を複製する。押し出し量は 0.02〜100 に丸める（NaN などの不正な値は 0.02） |
| ループ分割 | 四角形では対辺をたどって分割する。三角形に当たると、その三角形は2つの三角形に分割される。折れ目の辺は、分割後の両半分に折れ目を引き継ぐ。新しい頂点は、辺のベジェ曲線の中点に置く |
| 削除 | 点・辺は、接する面ごと削除する。すべての面は削除できない |
| ミラー編集 | x=0 の面について位置が一致する頂点を組にして、選択・移動・押し出しを対称に行う。x=0 上の頂点は、x を 0 に保つ |

### 面の制約

- 面は 3 辺か 4 辺だけ。押し出しもループ分割も、この制約を保つ
- 辺は 2 面までで共有する

### 検証表示

| 項目 | 内容 |
| --- | --- |
| 位置の隙間（G0） | 共有する辺の9点で、両側のパッチの位置の差の最大値（折れ目の辺も含む） |
| 法線の最大差（G1） | 折れ目でない共有辺の9点で、両側のパッチの法線の角度差の最大値。0.5° 未満を「G1 成立」とする |

## 実装メモ

| 項目 | 内容 |
| --- | --- |
| 構成 | `index.html`（画面）、`editor.js`（描画・入力・編集操作）、`mesh.js`（ケージの編集操作）、`gregory.js`（グレゴリーパッチの数学） |
| 描画 | 曲面は、CPU のソフトウェアラスタライザ。三角形ごとに深度バッファで塗り、スムースでは法線を遠近を考慮してピクセルごとに補間する。2倍の解像度で描いて縮小し、輪郭を滑らかにする。背面は法線で間引く。線・点・ミラー面などは Canvas 2D で重ねる |
| 外部依存 | フォントのみ。JavaScript のライブラリは使っていない |
| 実行 | ES モジュールを使うため、`file://` では動かない。ローカルでは `python3 -m http.server -d public` などで配信して確認する |
| 保存 | なし（ページを開き直すと初期状態に戻る） |

## 既知の制約

- 凹んだ角（頂点まわりの角度の合計が 360° を大きく超える鞍型の角）や、押し出し量の小さい薄い壁では、頂点の接平面を決められず、G1 が成立しないことがある。画面に「G1 不成立」と表示される。折れ目にすると解消する場合がある
- 折れ目と押し出しを組み合わせた複雑な形でも、G1 が崩れる場合がある
- 負の方向への押し出しは、既存の面と重なる形になる。これを避ける仕組みはない
- ミラー編集をいったん切って頂点を動かすと、対称が崩れた頂点は、組として扱われない
- 辺だけを単独で分割する操作はない（四角形が5辺になるため）。頂点を足す操作は、ループ分割だけ
- 背面の頂点や辺は、可視判定が法線による近似のため、選べない
- 曲面の描画は CPU で行うため、分割数を大きくすると重くなる（分割数 16 で、1フレームあたり 30ms 弱）。編集中は、初期値の 8 を勧める
- ハンドルの個別編集、保存と書き出し、5辺以上の面の分割には対応していない

## テスト

`npm test`（`tests/gregory-mesh-editor.test.mjs`）で、次の性質をランダムな入力で確認している。

- 任意の押し出し・ループ分割・削除・折れ目の操作列のあとで、面が 3〜4 辺、辺が 2 面までで共有、有向辺の向きが整合し、使われない頂点がなく、曲面の評価値が有限であること
- ループ分割だけの操作列のあとで、G1 の法線差が 1° 未満、G0 の隙間が 1e-9 未満であること
- 4形状（立方体・四角錐・三角柱・八面体）に、頂点のゆらぎと折れ目の入れ方をランダムに与えても、全辺の G0 が 1e-9 未満、滑らかな辺の G1 が 0.05° 未満であること
- 1枚の面の押し出しで、面と頂点がその面の辺の数だけ増えること
- 不正な入力（NaN・無限大・極端に大きい押し出し量、範囲外・整数でない・重複した面番号、存在しない辺）を、無視または範囲に丸めて、位相の正しいケージを保つこと
- ミラーの対応付けが、組になる頂点どうしで対称で、互いを指し合うこと

画面の操作（選択、ドラッグ、Undo/Redo、シェーディングの切り替え）は、ブラウザで手動確認した。自動テストの対象外。
